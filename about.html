사이트 소개

stateless tools는 개발·운영·콘텐츠 작업에서 자주 반복되는 변환과 점검 작업을 빠르게 끝내기 위해 만든 개인 프로젝트입니다.

운영자: taxijjang · 공개 저장소: github.com/taxijjang/all-tools-site

stateless tools is a personal project built to speed up the repetitive conversion and inspection work that shows up in development, operations, and content workflows.

Maintainer: taxijjang · Public repository: github.com/taxijjang/all-tools-site

왜 만들었나요?

PDF를 합치거나 스캔 문서에서 글자를 뽑아야 할 때, 검색하면 나오는 사이트 대부분이 파일을 자기 서버로 받아 처리합니다. 사내 문서나 계약서, 개인정보가 든 파일이라면 그걸 올릴 수 없습니다. 회사 정책이 막고 있거나, 막지 않더라도 그 파일이 어디에 얼마나 남는지 알 수 없기 때문입니다. 이 사이트는 그 문제를 없애려고 만들었습니다. 여기 있는 도구는 파일과 입력값을 서버로 보내지 않고 브라우저 안에서 끝냅니다. 페이지를 닫으면 아무것도 남지 않습니다.

Why this project exists

When you need to merge a PDF or pull text out of a scan, most sites that come up in search upload the file to their own server. For an internal document, a contract, or anything containing personal data, that is not an option — either policy forbids it, or you simply cannot tell where the file ends up or how long it stays. This site exists to remove that problem. The tools here finish inside your browser without sending files or input anywhere. Close the page and nothing remains.

언제 이 방식이 필요한가요?

올릴 수 없는 파일을 다룰 때

계약서 PDF를 쪼개거나, 사내 자료를 스캔한 이미지에서 글자를 뽑거나, 고객 데이터가 든 파일의 해시를 확인해야 할 때입니다. 파일이 기기를 떠나지 않으므로 반출 승인을 받을 일이 없습니다.

붙여넣는 값이 자격증명일 때

JWT 토큰, API 키가 든 요청, 운영 DB에서 뽑은 JSON을 검사하는 일이 잦습니다. 이런 값은 제3자 서버에 남으면 그 자체로 사고입니다. 디코딩과 검증을 브라우저에서 끝내는 이유입니다.

망이 분리되어 있을 때

내부망에서는 외부 API를 부르는 도구가 아예 동작하지 않습니다. 여기 도구는 페이지가 한 번 열리면 추가 통신 없이 계산하므로 그런 환경에서도 그대로 씁니다.

When this approach matters

Files you are not allowed to upload

Splitting a contract PDF, pulling text out of a scanned internal document, or hashing a file containing customer data. Because the file never leaves your device, there is no export approval to obtain.

When the value you paste is a credential

Inspecting a JWT, a request carrying an API key, or JSON pulled from a production database is routine work. Leaving those values on a third-party server is an incident in itself, which is why decoding and verification finish in the browser.

Networks without outbound access

On an isolated network, tools that call an external API simply do not work. These pages compute without further requests once loaded, so they keep working in that environment.

운영 기준

1. 브라우저 우선

서버 처리 없이 끝낼 수 있는 작업은 브라우저 메모리에서 완료하도록 설계합니다.

2. 과한 기능보다 자주 쓰는 기능

실제로 복사하거나 비교하고 검증하는 출력에 집중하고, 설정은 최대한 짧게 유지합니다.

3. 공개된 피드백 경로

오류와 개선 요청은 GitHub 저장소나 공개된 채널을 통해 확인하고 업데이트 방향을 정리합니다.

4. 심사 가능한 기본 정보

사이트 소개, 개인정보 처리 안내, 문의 페이지를 공개해 운영 주체와 정책을 확인할 수 있게 유지합니다.

현재 운영자는 taxijjang이며, 이 사이트는 개인 프로젝트로 계속 다듬는 중입니다.

Operating rules

1. Browser-first when possible

If a task can finish in browser memory without server-side processing, that is the preferred path.

2. Practical over bloated

The site prioritizes outputs people actually copy, compare, and verify instead of loading every page with extra controls.

3. Visible feedback routes

Bugs and improvement ideas are reviewed through public channels tied to the repository and site owner.

4. Reviewable site information

About, privacy, and contact pages are kept public so visitors and reviewers can understand ownership and policies.

The project is currently maintained by taxijjang as an evolving personal toolkit.
